# 기획: 대화에 맞춰 띄우는 개념 시각화

코디세이 동료 평가와 동료 학습 중에 두 사람이 나누는 대화를 듣고, 지금 이야기하는 컴퓨터공학 개념의 인터랙티브 시각화를 추천한다. 시각화는 대화에 나온 예시 값과 상황, 그리고 그 학습자의 지난 동료 평가 피드백에 맞춘 시작 상태로 열린다.

- 주제: 주제1. AI 기반 추천 서비스
- 출발점: 아이디어 09 「비유 확인 학습 도우미」. "비유가 어디까지 맞는지 그림으로 짚는다"에서 "지금 대화에 맞는 개념 시각화를 띄운다"로 중심을 옮겼다.

## 문제

- 코디세이 미션은 「과제 목표」에 "…을 스스로 설명할 수 있어야 한다"는 항목을 5~6개씩 둔다. 동료 평가는 이 항목들을 말로 설명하는 자리이고, 실제로는 미션 밖 주제까지 오가는 동료 학습처럼 흘러가는 경우가 많다.
- 해시 충돌, LRU 교체처럼 상태가 바뀌는 개념은 말로만 주고받으면 서로 다른 그림을 떠올리기 쉽다. 시각화 도구는 많지만, 대화 도중에 찾아 열고 예시 값을 다시 넣는 동안 대화가 끊긴다.

## 사용 장면

1. 평가 전에 피평가자가 자기 지난 동료 평가 피드백을 붙여넣는다(선택).
2. 시작 화면에서 피평가자를 고르고, 두 사람 모두 녹음에 동의한다. 동의하면 평가 내내 듣는다.
3. 노트북 한 대를 두 사람 사이에 두고 함께 본다. 대화에 맞는 시각화가 화면 옆에 추천 카드로 쌓이고, 두 사람 중 누구든 원할 때 눌러 펼친다.
4. 펼친 시각화는 대화의 값과 상황, 피평가자의 개념별 상태에 맞춘 시작 상태로 열리고, 두 사람이 직접 조작할 수 있다. 아래에는 그 개념을 확인하는 질문이 한 줄 붙는다.
5. 대화가 미션 밖 주제로 넘어가 맞는 시각화가 없으면 카드를 띄우지 않는다.

## 추천의 정의

- **후보**: 직접 만든 인터랙티브 개념 시각화. 첫 구현은 B5-1(해시·LRU 저장소)의 개념 2~3개다. 나머지 미션은 시각화 없이 확인 질문만 추천한다.
- **맥락**: 지금 대화. 어떤 개념을 이야기하는지, 어떤 값과 상황을 예로 들었는지.
- **사용자 데이터**: 피평가자의 지난 동료 평가 피드백. 피드백 문장을 개념에 잇고 개념마다 상태를 매긴다.
  - 새로 앎: 예) "IAM 같은 책임 분리 설정의 차이를 처음 알게 되었다" → IAM: 새로 앎
  - 헷갈림
  - 익숙함
- **순위**: 대화와 맞는 정도에 개념별 상태만큼 가중치를 곱한다(헷갈림 ×1.5, 새로 앎 ×1.2). 지금 말한 개념의 선행 개념을 헷갈렸다면, 대화에 나오지 않았어도 그 선행 개념을 후보에 넣는다. 예를 들어 해시표가 헷갈렸던 사람이 "LRU는 해시맵으로 만든다며?"라고 하면 해시표 카드가 LRU보다 먼저 뜬다.
- **시작 상태**: 새로 안 개념은 기본 단계부터, 헷갈렸던 개념은 헷갈리기 쉬운 단계(해시표는 충돌 순간, LRU는 교체 직전)에서, 익숙한 개념은 어려운 상황(긴 체인에서 조회, 조회로 바뀌는 교체 순서)부터 연다. 같은 대화라도 사람마다 다른 화면이 나온다.
- **AI가 하는 일**: 받아 적기(STT), 대화에서 개념 고르기, 말에서 예시 값과 상황을 뽑아 시작 상태로 옮기기, 피드백 문장을 개념별 상태로 분류하기. 예를 들어 "키 3과 13이 같은 칸에 들어가면?"이라고 하면, 그 값으로 해시표를 채우고 충돌 단계에서 멈춘 채 연다.
- **우리가 직접 만드는 것**: 외부에서 시작 상태를 지정할 수 있는 시각화, 난이도별 시작 상태, 말을 시작 상태로 옮기는 판정 규칙, 피드백 분류 기준, 추천 순위 규칙, 미션별 확인 질문.

## 시연할 개념 (B5-1)

- 해시표와 충돌 해결(체이닝)
- 이중 연결 리스트 + 해시맵으로 만든 LRU
- 여유가 있으면: TTL 만료 시간을 관리하는 힙

## 처리 흐름

1. 붙여넣은 피드백에서 이름을 지우고, 문장을 개념별 상태로 분류해 피평가자 프로필에 저장한다.
2. 마이크 하나로 녹음하고, 짧은 구간 단위로 STT를 돌린다. 추천은 몇 초 늦어도 되므로 완전한 실시간일 필요는 없다. 화자 분리는 하지 않는다.
3. 구간마다 개념을 고르고, 예시 값과 상황을 뽑는다.
4. 피평가자의 개념별 상태로 카드 순위와 시작 상태 난이도를 정한다.
5. 평가가 끝나면 이번 평가에서 다룬 개념과 펼친 카드를 피평가자 기록에 붙이고, 녹음 원문은 지운다.

## 모델과 서버

- L4 GPU(약 22.5GiB) 한 장에 Whisper와 오픈 8B LLM(4비트 양자화, 약 5~6GB)을 함께 올린다. fp16 그대로는 둘이 함께 들어가지 않는다.
- 녹음과 받아 적은 글이 서버 밖으로 나가지 않는다.
- 개념 고르기, 값 뽑기, 피드백 분류는 모두 정해진 형식을 채우는 일이라 작은 모델로 시작한다.

## 시연 영상 첫 장면

두 사람이 "3과 13이 같은 칸이면?"을 말로 주고받으며 헷갈려하다가, 옆에 뜬 카드를 누른다. 그 값으로 채워진 해시표가 충돌 단계에서 열린다.

## 개인화를 보여 주는 장면: 같은 대화, 두 학습자

피드백이 다른 두 학습자에게 같은 대화를 넣고 추천을 나란히 보여 준다. 주제 원문의 "사용자 데이터와 맥락"이 화면에서 바로 보이게 하는 장면이다.

- 학습자 A: 해시 충돌이 헷갈렸고, LRU는 처음 들었다.
- 학습자 B: 해시표는 익숙하고, LRU 교체 순서가 헷갈렸다.

| 대화 | A에게 | B에게 |
|---|---|---|
| "해시 테이블에 삼이랑 십삼 넣으면 같은 칸이잖아" | 해시표를 충돌 순간에서 연다 | 같은 3, 13에 키를 더 넣어 긴 체인에서 조회하는 상태로 연다 |
| "LRU 캐시는 해시맵이랑 연결 리스트로 만든다며?" | 1순위 해시표(LRU에 먼저 필요한 개념) | 1순위 LRU, 교체 직전에서 멈춤 |
| "용량 3에 A, B, C 넣고 A 조회하고 D 넣으면?" | LRU를 끝까지 실행한 상태 | LRU를 D를 넣기 직전에 멈추고 "누가 밀려날까요?"를 묻는다 |

## 비슷한 서비스와의 차이

- **[Google Visual Captions](https://research.google/pubs/visual-captions-augmenting-verbal-communication-with-on-the-fly-visuals/)**: 화상회의 자막을 받아 미세조정한 LLM이 대화의 "시각적 의도"를 예측하고 이미지를 추천한다. 자동으로 띄우기, 추천만 하기, 요청할 때만 추천하기 모드가 있고, [오픈소스](https://github.com/google/archat)다. 우리는 정지 이미지가 아니라 조작할 수 있는 개념 시각화를 띄우고, 대화의 값과 학습자의 지난 피드백으로 시작 상태를 맞춘다.
- **[AlgoVista](https://zenodo.org/records/18596497)**: 알고리즘 시각화에 LLM 설명과 평가를 붙인 도구다. 대화를 듣고 시각화를 고르지는 않는다.

## 범위

- **꼭**: 음성 입력, B5-1 시각화 2개(해시표, LRU)와 시작 상태 지정, 대화에서 개념·값 뽑기, 피드백 붙여넣기와 개념별 상태 분류, 추천 카드 화면, 동의 화면
- **여유 있으면**: 힙 시각화, 다른 미션의 확인 질문

## 역할 후보

- 음성: STT, 구간 처리
- 추천 엔진: 개념 고르기, 값·상황 뽑기, 순위 규칙
- 개인화: 피드백 분류 기준과 개념별 상태, 난이도별 시작 상태 규칙
- 시각화: 해시표, LRU(필요하면 힙)
- 화면·백엔드: 추천 카드, 피드백 붙여넣기, 동의 화면, 기록 저장, 모델 서빙(L4)

## 위험과 대응

- **말에서 값과 상황을 잘못 뽑는다.** 시각화마다 시작 상태의 형식(예: 해시표 크기, 넣을 키 목록, 멈출 단계)을 정해 두고, LLM이 그 형식만 채우게 한다. 형식에 맞지 않으면 기본 예시로 연다.
- **STT가 전문 용어를 틀린다.** "해시", "체이닝", "LRU" 같은 용어를 미션별 참고 문구로 미리 넣는다.
- **피드백에 개념 신호가 적다.** 피드백의 상당수는 태도나 감상이다. 개념 신호가 없으면 개인화 없이 맥락으로만 추천한다.
- **피드백 속 개인정보.** 피드백에는 다른 학습자의 이름과 글이 들어 있다. 붙여넣는 즉시 이름을 지우고, 개념별 상태만 저장한다.
- **녹음에 대한 거부감.** 시작 때 두 사람 모두 동의해야 녹음한다. 평가가 끝나면 녹음 원문은 지운다.
- **미션 원문 공개.** 미션 원문은 로그인해야 볼 수 있는 자료다. 운영진 확인 전까지 이 저장소에는 원문을 올리지 않고, 미션 코드와 우리가 직접 쓴 내용만 둔다.

## 정할 것

- 추천 후보를 "개념"에서 "장면"으로 늘릴지(후보안). 개념마다 시각화 장면을 3~4개 둔다(예: 해시표는 충돌 순간, 긴 체인과 적재율, 리해싱). 후보가 10개 안팎이 되어, 대화와 피드백으로 무엇을 띄울지 실제로 순위를 매기게 된다.
- 개념 목록과 피드백 분류 기준(새로 앎 / 헷갈림 / 익숙함을 가르는 표현)
- 시각화마다 난이도별 시작 상태를 몇 개 둘지
- 검증 숫자
